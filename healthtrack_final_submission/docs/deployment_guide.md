# HealthTrack — Deployment Guide

This guide covers deploying HealthTrack in two ways: a local/single-server
setup using the provided shell scripts, and a containerized setup using
Docker Compose. Both were exercised during this deliverable; see the
verification notes at the end of each section for what was actually run.

## 1. Prerequisites

- Python 3.11 or 3.12
- pip
- (Docker path only) Docker and Docker Compose
- (Production DB) PostgreSQL 14+ — SQLite is fine for local/dev use

## 2. Local / single-server deployment

### Step-by-step

1. **Clone or copy the repository** to the target machine.
2. **Run first-time setup:**
   ```bash
   ./scripts/setup.sh
   ```
   This creates a Python virtual environment (`venv/`), installs
   dependencies from `requirements.txt`, copies `deployment/.env.example`
   to `.env`, runs database migrations (`alembic upgrade head`), and
   trains the Random Forest risk model, saving it to
   `app/risk_model.joblib`.
3. **Edit `.env`** and set `DATABASE_URL` to your production database
   (see `deployment/.env.example` for the Postgres connection string
   format). Leave as SQLite only for local/dev use.
4. **Start the system:**
   ```bash
   ./scripts/run.sh
   ```
   This starts the FastAPI backend (default port 8000) and the Dash
   dashboard (default port 8050) together, and shuts both down cleanly
   on Ctrl+C.
5. **Verify:**
   - API health check: `curl http://localhost:8000/health`
   - Dashboard: open `http://localhost:8050` in a browser
   - API docs (auto-generated by FastAPI): `http://localhost:8000/docs`

For always-on production use, run the API and dashboard as separate
services under a process manager (systemd, supervisor) rather than the
combined `run.sh` script, so each can be restarted independently:

```bash
# API service
venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000

# Dashboard service
venv/bin/python dashboard/dash_app.py
```

### Verification performed

This flow was run end-to-end in a clean directory (fresh venv, no prior
`.db` or model file): setup completed without errors, both services came
up under `run.sh`, and `curl http://localhost:8000/health` and the
dashboard's root page both returned HTTP 200 while the two services were
talking to each other over HTTP.

## 3. Docker Compose deployment

The `deployment/` folder includes `Dockerfile.api`, `Dockerfile.dashboard`,
and `docker-compose.yml`, which together bring up three services:
PostgreSQL, the FastAPI backend, and the Dash dashboard.

```bash
cd deployment
docker compose up --build
```

The API container runs `alembic upgrade head` automatically on startup
before launching uvicorn, so migrations are applied on every deploy.

- API: `http://localhost:8000`
- Dashboard: `http://localhost:8050`
- Postgres: `localhost:5432` (internal service name `db`)

**Before using in production:** change the default Postgres credentials
in `docker-compose.yml` (`POSTGRES_PASSWORD` and the matching
`DATABASE_URL`) — the checked-in values are placeholders for local
testing only.

### Verification performed — known limitation

The `docker-compose.yml` and both Dockerfiles were written and the compose
file's YAML was validated for correct syntax and service structure, but
Docker itself was not available in the environment used to build this
deliverable, so the containers were not actually built or run. **Before
relying on this path in production, run `docker compose up --build` once
in a real environment and confirm all three services start and the API
can reach Postgres.** The local/single-server path (Section 2) is the
one that was fully verified end-to-end.

## 4. Post-deployment checklist

- [ ] `DATABASE_URL` points to the production database, not SQLite
- [ ] Database migrations applied (`alembic upgrade head` or automatic via Docker)
- [ ] Risk model artifact present at `app/risk_model.joblib` (retrain with
      `python scripts/train_risk_model.py` if missing)
- [ ] `.env` reviewed — no default/placeholder credentials in production
- [ ] `/health` endpoint returns 200
- [ ] Dashboard loads and shows "Connected to ... — last refresh OK"
- [ ] Test suite passes against the target environment: `./scripts/test.sh`
